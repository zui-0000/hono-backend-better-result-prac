# 小話: なぜ 1 時間なのか — Bearer は「持参人」

[README](README.md) の補足。本編を読むのに必須ではないけれど、
「アクセストークンの寿命 1 時間」が天下り的に見えた人向け。

答えるのはこの 3 つ。

| 疑問                                     | 短い答え                                                         |
| ---------------------------------------- | ---------------------------------------------------------------- |
| 寿命 1 時間は一般的？                    | 主要ベンダーの最頻値。ただし**数字より「何と引き換えか」が本題** |
| 用途は通行証みたいなもの？               | そう。ただし**窓口で照会しない**通行証                           |
| `Authorization: Bearer …` に詰めて送る？ | そう。契約もコードもそれで固定してある                           |

**この 3 つは同じ 1 つの話。** 下から順に読むと理由が繋がるので、
実装の話 → 性質の話 → 数字の話、の順に置いた。

---

## 1. どう送るか — `Authorization: Bearer`

```bash
curl -H "Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJzdWIi…" \
     http://localhost:3000/users/019fa5bc-0000-7000-8000-000000000000
```

契約とコードの両方で固定されている。

```tsp
// schema/src/main.tsp — 5 経路が宣言している
@useAuth(BearerAuth)
```

```ts
// src/shared/presentation/handler/verify-bearer.ts
const BEARER_PATTERN = /^Bearer (.+)$/u;
const header = c.req.header(HttpHeader.Authorization);
```

`Bearer ` の後ろを 1 つ取るだけ。**ヘッダが無い / 形が違う / 検証に落ちる、すべて同じ 401**
（どれで落ちたかを教えると、攻撃側に手がかりを渡すことになる）。

**例外が 1 つある。`POST /auth/refresh` だけは Bearer を使わない。**
アクセストークンが切れたから来ているのに Bearer を要求したら詰むので、
あそこは Cookie の券で認証する。

---

## 2. どういう性質のものか — 「持参人」という言葉

`Bearer` を訳すと **「持参人」**。無記名債券 (bearer bond) と同じ用法で、意味はこう。

> **持参した人が誰であれ、持っていれば通す。**

通行証には 2 種類ある。この違いが設計のすべてを決める。

|              | 社員証タイプ         | **リストバンドタイプ**           |
| ------------ | -------------------- | -------------------------------- |
| 提示されたら | 窓口で名簿に照会する | **見た目だけで判断。照会しない** |
| 偽造対策     | 名簿にあるか         | 複製しにくいこと (＝署名)        |
| 落としたら   | 無効にできる         | **拾った人が入れる**             |
| 取り消し     | 名簿から消す         | **できない**                     |
| コスト       | 毎回ストアへ往復     | HMAC の計算 1 回                 |

**うちのアクセストークンは完全に右側。** `verify-bearer.ts` は DB を一切引かない。
速いのはそのおかげで、取り消せないのもそのせい。

---

## 3. だから寿命で我慢する — 1 時間の相場

取り消せない以上、寿命はそのまま**「ログアウトが効くまでの最大遅延」**になる。
まず世間の相場から。

| 実装               | 既定値               |
| ------------------ | -------------------- |
| Keycloak           | **5 分**             |
| Google OAuth 2.0   | 1 時間               |
| Okta               | 1 時間               |
| AWS Cognito        | 1 時間 (5 分〜1 日)  |
| **このプロダクト** | **1 時間**           |
| Auth0              | 24 時間 (最大 30 日) |

**最頻値は 1 時間で、うちもそこに合わせている。** RFC 6749 は寿命を規定しておらず、
[RFC 9700 (BCP 240)](https://datatracker.ietf.org/doc/rfc9700/) が「短くしろ」と
言っているだけで、具体的な秒数は決めていない。

### 15 分から 1 時間に変えた経緯

最初は 15 分にしていた。**短いこと自体に実害が無かった**ので下限寄りに置いていたが、
「短すぎる」という感覚が残ったため、最頻値である 1 時間へ寄せた。

同時に検討して**見送った案が「24 時間」**。これは採れない。

| 機能                         | 1 時間      | 24 時間にすると  |
| ---------------------------- | ----------- | ---------------- |
| ログアウト                   | 最大 1 時間 | **最大 24 時間** |
| パスワード変更で他端末を切る | 最大 1 時間 | **最大 24 時間** |
| 退会でセッションを切る       | 最大 1 時間 | **最大 24 時間** |
| 盗難検出でセッションを切る   | 最大 1 時間 | **最大 24 時間** |

2 行目が決定打。**パスワードを変える動機の大半は「漏れたかもしれない」**なので、
それが 24 時間効かないなら機能として成立しない。

もう 1 つ、**長いアクセストークンはリフレッシュ側の精度も落とす。**
サーバが「まだ使っている」を知る手段はリフレッシュが来ることだけなので、
24 時間に 1 回しか来ないと「最終操作から 2 日」が 1 日ぶんぶれる。
**短いアクセストークンこそがスライド窓を「最終操作」に一致させている。**

### つまみは 3 つあって連動している

| つまみ               | 短くすると                         | 長くすると |
| -------------------- | ---------------------------------- | ---------- |
| ログアウトの効き     | 速い                               | 遅い       |
| リフレッシュの頻度   | 増える (1 時間なら **1 日 24 回**) | 減る       |
| 漏れたときの被害の窓 | 狭い                               | 広い       |

1 時間は**妥協点であって正解ではない。**

### 「ログアウトを即座に効かせたい」と言われたら

寿命を 1 分に縮めるのは悪手。正解は**失効リスト (denylist) を持つこと**。
ただし、それをやると毎回ストアを引くので **JWT を使う理由がほぼ消える**
（「照会しないから速い」が唯一の売りなので）。

だから分岐はこうなる。

```text
ログアウトの即時性が要る？
  ├ いらない → JWT + 短い寿命          ← いまここ
  └ 要る     → セッション ID + ストア   (＝ JWT をやめる)
```

**中途半端に「JWT だけど毎回 denylist を引く」をやると、両方の悪いところ取りになる。**
取り消せない不便さを抱えたまま、速さだけ失う。

---

## まとめ

```text
持参人式だから (2)
  → 落としても取り消せない
    → 寿命を短くして我慢するしかない (3)
      → 切れるたびに取り直すので、毎回ヘッダに詰めて送る (1)
```

寿命 1 時間は「安全のためになんとなく短くした」数字ではなく、
**取り消せないという性質の埋め合わせ**として置いてある。
伸ばすときは「取り消しが何時間効かなくなるか」で判断すること。
